## В2. `crm_send_owner_message`

Код: `tasks/quiet.py::send_owner_message`. Відповіді (приклади вигадані):

```json
// удень, без urgent — одразу, у стелю не рахується
{"sent": true}

// о 23:00 — у черзу; вийде першим блоком «Від Claude» у ранковому плані (DAILY_RUN_HOUR, типово 08:00)
{"sent": false, "queued_until": "2026-10-18T08:00:00+02:00", "reason": "quiet_hours"}

// urgent уночі — одразу, але рахується в денну стелю
{"sent": true, "urgent": true}

// urgent, стеля вичерпана — теж у черзу
{"sent": false, "queued_until": "2026-10-18T08:00:00+02:00", "reason": "daily_cap"}
```

Коли черга виходить (`queued_until`):
- **Ранковий план буде** (`task_settings.enabled` і `plan_enabled`): у час плану. Блок «Від Claude» іде першим. Якщо разом із планом повідомлення задовге для Telegram, «Від Claude» іде окремим повідомленням перед планом.
- **Плану немає:** одразу після кінця тиші (о 07:30). Задача планувальника `quiet_release` перевіряє чергу кожні 15 хв.
- **План мав бути, але не дійшов** за годину після `DAILY_RUN_HOUR`: черга виходить сама.
- **Telegram не прийняв повідомлення:** черга повертається (`quiet.restore`) і чекає наступної спроби.

## В3. Нічні пропозиції задач

Що змінилося в пропозиціях (`task_intake.maybe_suggest`):
- **Удень** кожна пропозиція йде в денну стелю.
- **Уночі або при вичерпаній стелі** пропозиція не надсилається, а чекає ранку. Раніше вона приходила вночі без звуку.
- **Картка контакту, який зараз «на паузі»** (кнопки «📅 / ⏰ / ➕ Задача» з `_detect_incoming_intent`), уночі теж не надсилається. Те, на що вона пропонувала діяти, стає пропозицією в черзі. У режимі `auto` задача створюється одразу, і пропонувати нічого не треба.

Блок «За ніч» у ранковому плані:

```
🌙 За ніч: 7 пропозицій
1. 👤 Контакт · я винен · строк 20.10 (тобі написали)
«Надішли договір до 20.10»
…
[➕ Задача 1] [📅 1] [✖ 1]
…
[Ще… (2)]
```

- Кнопки мають вигляд `tn:add|cal|x:<id>` і `tn:more`.
- Натиснута кнопка прибирає з повідомлення лише свій рядок (через `editMessageReplyMarkup`). Текст плану й кнопки задач `tk:` лишаються.
- «Ще…» надсилає наступні п'ять із продовженням нумерації.
- Блок «За ніч» рахується в стелю як одне повідомлення.

Дублікати перевіряються за ключем `tgb:<chat_id>:<message_id>`. Те саме повідомлення не пропонується двічі:
- ні вночі, ні вдень;
- навіть після повторної доставки апдейта.

Денна пропозиція теж лишає рядок у `held_messages` (уже виданий), саме для цієї перевірки.

## В5. «Відкрити чат» для чатів без вхідного за 24 год

`telegram_bot.service.can_reply` перевіряє, чи було вхідне Telegram-повідомлення від контакту за останні 24 год (`source='telegram'`). Якщо не було, картка чернетки виглядає так:

```
[🔗 Відкрити чат] [📋 Скопіювати текст]
[✔ Надіслав сам] [⏭ Пропустити]
[🌐 Переклад] [🚫 Стоп-лист]
```

- **Кнопки «✅ Надіслати» немає.**
- **«Відкрити чат»** веде на `https://t.me/<username>`, а якщо username немає — на `tg://user?id=<id>`. Telegram може відхилити `tg://` через налаштування приватності людини; тоді картка надсилається вдруге, без цієї кнопки (`send_draft_card`).
- **«Надіслав сам»** записує текст в історію як вихідну взаємодію (як `crm_log_interaction`) і закриває чернетку (`sent`). Якщо Business-з'єднання вже принесло цей вихідний з телефона власника, другого запису не буде.
- **Де діє:**
  - `crm_save_message_draft` (у відповіді прямо сказано, що бот сюди не напише);
  - «Попроси …»;
  - картки черги обходу;
  - переклад і переписування чернетки;
  - «✍️ Скласти відповідь» для контакту на паузі.

## Що не зроблено й чому

- **Часовий пояс власника.** Окремого налаштування в коді немає. Тиша, як і весь розклад (план о 08:00, звірка о 13:00, коуч), живе за локальним часом сервера. Залишив цю домовленість, бо змінювати пояс лише для тиші розвело б її з рештою розкладу. Див. питання нижче.
- **«Скопіювати текст» для довгих чернеток.** `CopyTextButton` приймає до 256 символів. Довшу чернетку копіюють із самої картки, кнопки копіювання тоді немає.
- **Картка «на паузі» вночі.** Чернетка-відповідь (кнопка «✍️ Скласти відповідь») уночі не створюється. Уранці в «За ніч» лишаються ➕ і 📅; відповісти можна з самого чату.
- **Приймання №2** (сесія Claude без `?profile` бачить усі шість інструментів синку й `crm_update_contact`) у тестах перевірено через `tools_for(None)`. Наживо — лише після деплою: конектору claude.ai треба оновити список інструментів.
